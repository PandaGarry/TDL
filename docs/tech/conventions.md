# Договорённости (conventions)

Статус: **В работе**. Смысл документа: чтобы проект через год читался так же
легко, как в первый день, и чтобы Godot не устраивал сюрпризов с путями.

## Имена файлов и папок

- Всё в проекте Godot: `snake_case`, латиница, без пробелов —
  `main_menu.tscn`, `health_component.gd`, `spr_hero_idle.png`.
  Причины: чувствительность к регистру на Linux/вебе, автодополнение,
  предсказуемые пути `res://`.
- Скрипт сцены носит то же имя, что сцена (`main_menu.gd` <-> `main_menu.tscn`).
- Папки `scenes/` и `scripts/` зеркалят друг друга по смыслу (`ui/`, `characters/`...).
- Имена из лора (персонажи, места) в файлах — транслитом/английским ключом
  из `docs/lore/glossary.md`, а не «как получится».
- Префиксы ассетов по желанию команды: `spr_` спрайты, `tex_` текстуры,
  `mus_`/`sfx_`/`amb_` аудио — главное, единообразно.

## GDScript

- Следуем официальному гайдлайну GDScript: `snake_case` для функций/переменных,
  `PascalCase` для классов и узлов в сценах, `CONSTANT_CASE` для констант.
- Типизация: типы аргументов/возвратов и переменных указываем, где это не
  превращает код в шум. Статическая проверка ловит ошибки раньше запуска.
- Табы для отступов (`.editorconfig` настроен), `LF` окончания строк.
- Комментарии `##` — документация API (видна в редакторе), `#` — пояснения
  «почему так», а не пересказ кода.
- Приватное — с подчёркиванием (`_loading_path`), как принято в GDScript.
- Никаких «магических строк» путей к сценам, разбросанных по коду:
  константы в одном месте у владельца логики переходов.
- `print()` для отладки не коммитим в релизный код; для логов —
  `push_warning`/`push_error` при реальных проблемах.

## Сцены

- Корневой узел сцены называет сцену (`MainMenu`), а не `Node2D`/`Control`.
- Ссылки на дочерние узлы — уникальные имена (`%NewGameButton`) или
  `@export`, а не длинные хрупкие пути вида `$A/B/C/D`.
- Настройки в инспекторе, которые должен крутить дизайнер, — `@export`
  с понятным именем и, где уместно, диапазоном.

## Git

- Работа ведётся в ветках; в `main` — только рабочее состояние проекта.
- Сообщения коммитов: коротко «что и зачем» (например,
  `Диалоги: первый NPC у причала` / `Fix: пауза не снималась из меню`).
- Коммитить вместе: сцену + её скрипт + `.import` файлы новых ассетов.
  Папка `.godot/` в гите не живёт (она в `.gitignore`).
- Перед коммитом тяжёлых ассетов подумать про Git LFS
  (см. `build_and_export.md`); порог и момент включения фиксируем в decisions.
- Файлы внутри `addons/<плагин>/` руками не редактируем.

## Документация

- Решил что-то важное в чате/голове — записал в `docs/` в тот же день.
- Новое имя/термин мира — сразу в `docs/lore/glossary.md`.
- Идея «было бы круто» без решения делать — в `production/backlog.md`,
  а не в GDD (бережём scope).
