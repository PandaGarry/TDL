# Сборка и экспорт

Статус: **Черновик**. Экспорт-пресетов (`export_presets.cfg`) пока нет
сознательно: они создаются под конкретные платформы, а их список мы утвердим
с концепцией. Здесь — как и когда это делать.

## Подготовка (один раз на машину)

1. Godot **4.7.x** standard (тот же мажор/минор, что в `project.godot`).
2. Editor -> Manage Export Templates -> Download and Install
   (шаблоны должны совпадать с версией редактора один-в-один).

## Автопроверка проекта настоящим Godot (CI)

При каждом пуше GitHub Actions (`.github/workflows/godot-validate.yml`)
на чистом Linux-раннере:

1. скачивает официальный **Godot 4.7.2-stable** и сверяет SHA512;
2. `godot --headless --path . --import` — импорт проекта редактором;
3. запускает `tests/smoke/project_validation.tscn` — сцена загружает все
   скрипты из `scripts/` через ResourceLoader и заставляет движок
   скомпилировать их в реальном контексте проекта (с автозагрузками).
   Отдельный `--check-only --script` для файлов проекта не используем:
   вне обычного прогона компилятор не видит имена автозагрузок и даёт
   ложные «Identifier not found» на валидном коде;
4. делает smoke-запуск главной сцены (`--quit-after 30`) и ищет в логах
   `SCRIPT ERROR` / ошибки загрузки. Логи сохраняются артефактом Actions.

Первый зелёный прогон: run `39494636584`, 2026-10-20. Локально тот же набор
проверок: `tools/check_project.sh [путь_к_godot]`.

Зачем CI, а не движок внутри рабочей песочницы Arena: бинарные релизы GitHub
отдаются через `release-assets.githubusercontent.com`, недоступный из
песочницы по allowlist сети. Подробности и обоснование —
`docs/production/decisions.md`. Для разработки на своей машине ставь Godot
как обычно (см. выше) — ограничение только у песочницы.

## Экспорт

1. Project -> Export -> Add preset (Windows Desktop / Linux / macOS / Web — по списку платформ из GDD).
2. Включить пресет-файл `export_presets.cfg` в коммит после создания —
   это часть конфигурации проекта, а не мусор. (Он не в `.gitignore`.)
3. Билды складывать в `build/<платформа>/` — папка `build/` игнорируется гитом.
4. Имя билда: `tdl_<версия>_<платформа>` до выбора названия, дальше —
   по имени игры. Версию игры ведём в `project.godot`
   (Application -> Config -> Version) с первого публичного билда.

## Чек-лист перед тем, как отдать билд людям

- [ ] Игра запускается с чистого профиля (нет старых `user://` сейвов/настроек)
- [ ] Путь «меню -> игра -> пауза -> выход» работает целиком
- [ ] Нет `print()` отладочного спама и красных ошибок в консоли
- [ ] Громкости по умолчанию не оглушают, `Esc`/пауза работает
- [ ] Проверено на машине/системе, где нет редактора Godot

## Git LFS — когда включать

Сейчас репозиторий лёгкий (код, текст, плагины). LFS включаем, когда
появятся тяжёлые бинарные ассеты (большие текстуры, звук, модели),
чтобы не раздувать историю git:

1. `git lfs install` на каждой машине разработки.
2. В `.gitattributes` раскомментировать LFS-строки для нужных типов.
3. Решение и дату зафиксировать в `docs/production/decisions.md`.

До этого момента: исходники арта (`.blend`, `.psd`, записи звука)
храним осознанно — либо в репозитории, пока они маленькие, либо рядом
с проектом вне гита, с договорённостью, где у них «дом».
